## Findings considered and rejected

- Rewrite the whole app to Expo Router immediately: rejected for first release. The current React Navigation route tree is already established; changing navigation framework during a migration increases release risk.
- Replace MMKV with SecureStore/AsyncStorage immediately: rejected for first release. Preserving existing login/session storage is more important than simplifying dependencies.
- Keep Cashfree in the first Expo release: rejected based on owner direction. Payment can be deferred or disabled until the Expo app update path is stable.
- Use Expo Go as the migration target: rejected. Native modules and production notification behavior require development builds/prebuild/EAS, not Expo Go.
